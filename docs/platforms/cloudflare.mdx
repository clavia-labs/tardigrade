Each actor instance runs in a SQLite-backed Durable Object. The host keeps a supervisor journal and separate logical thread journals in that object's storage. The Worker routes an instance ID to its `ActorDO`:

```ts title="worker.ts"
import { DurableObject } from "cloudflare:workers"
import { actorContext } from "tardie/agent"
import { createCloudflareHost, methodHttp } from "tardie/platform/cloudflare"
import definition from "./actor"
import { services } from "./services"

interface Env {
  readonly ACTORS: DurableObjectNamespace<ActorDO>
  readonly TARDIGRADE_CONFIG: { readonly models: unknown } | string
  readonly TARDIGRADE_TOKEN?: string
  readonly [key: string]: unknown
}

export class ActorDO extends DurableObject<Env> {
  private readonly host = createCloudflareHost({
    actor: definition,
    actorContext,
    storage: this.ctx.storage,
    services: () => services((typeof this.env.TARDIGRADE_CONFIG === "string" ? JSON.parse(this.env.TARDIGRADE_CONFIG) : this.env.TARDIGRADE_CONFIG).models, this.env),
  })
  private readonly handler = methodHttp(this.host, {
    ...(this.env.TARDIGRADE_TOKEN ? { token: this.env.TARDIGRADE_TOKEN } : {}),
  })
  fetch(request: Request): Promise<Response> { return this.handler(request) }
}

export default {
  fetch(request: Request, env: Env): Promise<Response> | Response {
    const instance = /^\/v1\/actors\/([^/]+)\/threads(?:\/|$)/.exec(new URL(request.url).pathname)?.[1] ?? "main"
    return env.ACTORS.getByName(decodeURIComponent(instance)).fetch(request)
  },
}
```

`services` comes from the generated `services.ts` and supplies model and tool implementations. `actorContext` selects the services visible to agent setup. `methodHttp` uses the methods returned by the actor; it needs no separate method registry.

## Verify locally

Start with a project from the [Quickstart](/docs/quickstart), then install Wrangler in that project. Use a release that supports the `compatibility_date` in `wrangler.jsonc`; [updating Wrangler](https://developers.cloudflare.com/workers/wrangler/install-and-update/) also updates its local runtime:

```bash
bun add --dev wrangler@latest
```

Add `TARDIGRADE_TOKEN` and each configured provider credential to `.dev.vars`. Interactive `tdg setup` saves credentials there; credentials supplied only through the environment must also be available to Wrangler. Set a token and use the same value with the CLI's `--token` option. The generated Worker enables bearer authentication when `TARDIGRADE_TOKEN` is present.

Start the Worker:

```bash
bun run dev:cloudflare
```

Set `TARDIGRADE_TOKEN` in the calling shell to the value saved in `.dev.vars`. Wrangler reads that file for the Worker; it does not export its values to another shell. Use the URL printed by Wrangler when allocating and calling a thread. `/healthz` is public; when authentication is enabled, the remaining commands require the token from `.dev.vars`:

```bash
curl http://localhost:8787/healthz
tdg thread create --name quickstart --url http://localhost:8787 --token "$TARDIGRADE_TOKEN"
tdg call message '{"text":"What is the weather in Singapore?"}' --thread quickstart --url http://localhost:8787 --token "$TARDIGRADE_TOKEN"
```

## Configure

`tdg init` creates `wrangler.jsonc` and the Worker entry for your actor. Run `tdg setup` to select a model and write its visible configuration to the project.

The generated manifest binds `ACTORS` to the exported `ActorDO` class and declares its SQLite migration. Model metadata comes from `models.lock.json`, bundled with the Worker.

Store the Tardigrade token and each model provider credential as Wrangler secrets:

```bash
bunx wrangler secret put TARDIGRADE_TOKEN
bunx wrangler secret put OPENAI_API_KEY
```

Use the credential name configured for your provider in place of `OPENAI_API_KEY`.

## Deploy

```bash variant="single"
bunx wrangler deploy
```

The deployed Worker exposes the same thread creation, method invocation, cancellation, and event routes used during local development.
