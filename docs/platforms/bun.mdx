The Bun platform runs a Tardigrade actor as a process backed by SQLite. Each actor instance has a directory database, and each thread has its own event log, workspace, runtime, and alarm state.

## Run locally

`tdg init` creates a `server.ts` entry that mounts `actor.ts` and serves its API. Start it through the generated package script:

```bash variant="single"
bun run dev
```

The script loads `.dev.vars`, watches the TypeScript sources, and restarts the server after an edit. The server listens on port `4242` by default. Its health endpoint is available at `/healthz`.

Run the Cloudflare Worker locally when you need the Durable Object runtime:

```bash variant="single"
bun run dev:cloudflare
```

## Provide application services

An actor that requires an application Effect service can merge its layer with the model services in `server.ts`:

```ts title="server.ts"
import { Layer, Schedule } from "effect"
import { createBunHost, remoteBackupFromKeyValueStore } from "tardie/bun"
import { bunModelServices } from "tardie/server/model-services"
import { AppConfig } from "./application"
import { remoteStore } from "./remote-store"
import definition from "./actor"

const { config, layers, api } = await bunModelServices({
  env: process.env
})
const host = await createBunHost({
  actor: definition,
  storage: config.actorData,
  // backup is optional and publishes local checkpoints in the background.
  backup: {
    layer: remoteBackupFromKeyValueStore(definition.name).pipe(
      Layer.provide(remoteStore)
    ),
    schedule: Schedule.spaced("30 seconds")
  },
  driver: { maxConcurrentThreads: config.maxConcurrentThreads },
  layersFor: (thread, instance) => Layer.mergeAll(
    layers,
    Layer.succeed(AppConfig, { thread, instance })
  )
})
```

### Application services

`layersFor(thread, instance)` combines model services with your own services. Here, `AppConfig` makes the thread and instance IDs available to the actor.

### HTTP

Pass `api` to `serve(host, { port: config.port, api })` for model discovery and live inference output. Close the HTTP server before the host. See the [Actors guide](/docs/actors#serve-over-http).

### Optional backup

`remoteStore` is your remote `KeyValueStore` layer. You can also provide a custom `RemoteBackup` through `backup.layer`.

Backup snapshots the default local storage layout in a worker and retries uploads in the background. Local commits continue during remote outages.

## Storage

Generated servers store actor instances under `.tardigrade/data/`. Each instance database filename is the base64url encoding of `[actor, instance]` as JSON, followed by `.sqlite`. Thread databases live in a sibling `<instance-database>.threads/` directory, with base64url-encoded thread IDs as filenames.

The host persists events before running the work they enable, so it can resume unfinished work after the process restarts.

## Configure

`tdg setup` writes model configuration to `wrangler.jsonc` and local credentials to `.dev.vars`. The generated development script loads `.dev.vars`. A hosted process can provide the same credential names through its environment.

Set `PORT` to change the HTTP port and `TARDIGRADE_ACTOR_DATA` to change the storage directory used by the generated server.
