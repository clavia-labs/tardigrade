A budget combines a numeric log projection with a limit and a policy for unknown usage. The projection measures what happened. The budget decides whether another action can proceed. `spendUsd` and `toolCalls` use the same constraint evaluation as application projections.

## Compose limits

The application supplies `search` and `browse` in this example:

```ts
import { budget, infer, nativeOutput, spendUsd, system, toolCalls } from "tardie/agent"
import { browse, search } from "./tools"

const assistant = infer([
  system("Answer concisely."),
  budget(spendUsd, { limit: 0.5, onUnknown: "block" }),
  budget([search, browse], toolCalls, { limit: 10 }),
  nativeOutput
])
```

The dollar budget checks completed spend before the next native inference attempt. The tool budget checks each call before dispatching a tool in its child components. Their measurements and consequences differ:

| Form | Measurement | At the limit |
| --- | --- | --- |
| `budget(spendUsd, { limit })` | Recorded cost of native model attempts in the current turn | Refuse another inference attempt; a completed answer can finish |
| `budget(components, toolCalls, { limit })` | Admitted calls to child tools in the current turn | Refuse excess tool calls; allow the agent to answer or request a grant |
| `budget(projection, { limit, name })` | The application's projection value | Refuse another inference attempt |

An inference budget admits work while its value is below the limit. The call that crosses a dollar threshold can complete and cost more than the remaining allowance. Multiple inference budgets inspect their respective projections, and any blocked constraint refuses the next attempt. Give repeated constraints distinct `name` values because component identities must be unique within an actor. Repeated dollar constraints inspect the same recorded spend; they do not create separate spending pools.

`spendUsd` accounts for native `ModelReturned` events. Compaction summaries and model calls made directly by other components remain outside its accounting and admission. Context compaction has its own policy because retained context can shrink while paid usage accumulates.

## Unknown cost and retries

`DEFAULT_BUDGET_ON_UNKNOWN` is `"block"`. A missing projection value means the measurement is unknown. With `onUnknown: "block"`, another inference attempt is refused. With `onUnknown: "admit"`, it can proceed while the recorded measurement stays unknown. The applied inference policies are retained in `ModelCalled.admission`; a refusal records its policy in `TurnFailed`.

A failed request with no usage evidence can still have incurred a provider charge. Failure alone does not establish zero cost. A retryable failure with known zero cost can retry below the threshold. A retryable failure with missing cost needs an explicit allowance:

```ts
budget(spendUsd, { limit: 0.5, onUnknown: "admit" })
```

This permits further attempts after unknown cost, subject to the inference retry policy. It does not make the missing cost zero or prove that total spend remains below the threshold. When the aggregate is unknown, this policy also admits work if its known subtotal has already crossed the limit. When the aggregate is known, spend at or above the limit refuses another attempt.

A binding with neither a pricing table nor a cost reader can leave every attempt's cost unknown. Under the default policy, the first attempt is admitted, but another attempt in the turn is refused. Supply cost evidence or choose `onUnknown` explicitly for that binding.

A model integration can supply authoritative cost evidence through its finish reader:

```ts
const settings = {
  cost: (finish) => readReceipt(finish) ?? {}
}
```

The reader returns `costUsd` for the logical attempt's effective total and can retain `reportedCostUsd`, `estimatedCostUsd`, and `costSource`. Returning `{}` records an unknown total and prevents fallback repricing. Returning `undefined` leaves provider reports and pricing-table fallback in effect. Explicit `costUsd: 0` is evidence of a free attempt. Reservations and deterministic image-token estimates are separate from actual cost evidence.

## Tool reservations and grants

The tool form reserves each admitted call in log order, including calls in the same model batch. A rejected call consumes no allowance, and a later grant cannot change its earlier decision. The framework's `request_budget` tool is outside the guarded subtree and is exempt from the tool-call count. That name is reserved for escalation inside a budget wrapper.

```ts
import { budget, caller, toolCalls } from "tardie/agent"

budget([search, browse], toolCalls, { limit: 10, authority: caller() })
```

The initial allowance and applied policy are recorded as `BudgetGranted`. Its recorded limit and unknown-usage policy apply when the turn is replayed. Further grants add to the allowance. On an escalatable turn, `caller()` resolves the authority from the accepted message invocation; the agent can request more allowance after reaching the wall. A denied request leaves the tools unavailable and the agent can finish its answer. The default tool-call allowance is `DEFAULT_BUDGET_POLICY.limit`, which is 40.

The three-argument tool form also accepts an application projection. It receives current-turn events with tool calls limited to the wrapped tools. Admission tentatively steps each call and retains that step only when the projected demand fits the allowance. Tool allowances and grants use positive integer demand units. A projection that reserves demand on `ToolCalled` can bound a concurrent batch. A projection that measures only completed usage cannot reserve costs that it has not observed.

A tool refusal records the effective allowance, measurement, and reason in `BudgetExhausted.policy`. For an unknown application measurement, `used` and `policy.observed` are `null`. Numeric measurements retain numeric `used` values, including the existing tool-call form.

## Application projections

Use the framework's existing `Projection<State, number | undefined>` contract. No budget-specific event reducer is required. The projection owns its history scope and resets. For example, this projection counts native model attempts across the thread:

```ts
import type { Projection } from "tardie/core/projection"
import { budget } from "tardie/agent"

const modelAttempts: Projection<number, number> = {
  initial: () => 0,
  step: (count, event) => event.type === "ModelCalled" ? count + 1 : count,
  output: (count) => count
}

const attempts = budget(modelAttempts, { limit: 20, name: "modelAttempts" })
```

The budget retains the projection's state as events arrive and reconstructs it from the same log during replay. A measurement must be a finite nonnegative number or `undefined`; invalid numeric values throw a projection error. Return `undefined` when evidence is insufficient to produce a measurement. Set `name` to identify the constraint in diagnostics.

## Existing call forms

`budget({ usd: 0.5 })` remains an adapter for the dollar projection with the conservative unknown-cost default. `budget([search, browse], { limit: 10, authority: caller() })` remains an adapter for the tool-call projection. Existing callers can keep these forms while using the shared constraint implementation.
