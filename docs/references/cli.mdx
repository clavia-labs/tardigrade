## Install

<Command value="bun add -g tardie" label="Install the Tardigrade CLI" />

Use `bunx tardie <command>` to run a command without installing it. Tardigrade requires Bun 1.4 or later.

Commands that print data accept `--json` where their help lists it. Remote commands accept `--url`, `--token`, and `--actor`. The actor instance defaults to `main`. Run `tdg <command> --help` for every option.

## Initialize and configure

Run interactive initialization to create a directory, choose the first provider and model, and write the generated actor:

```bash
tdg init tardie-agent --template quickstart
cd tardie-agent
bun run dev
```

An agent or CI job can supply the connection as JSON. The JSON names secret environment variables and contains no secret values:

```bash
tdg init tardie-agent \
  --template quickstart \
  --provider openrouter \
  --provider-config '{"env":["OPENROUTER_API_KEY"]}' \
  --default-model anthropic/claude-sonnet-4.6
cd tardie-agent
```

Non-interactive initialization requires all three provider options. It does not read or write the named credential. Set each credential in the environment that runs the server.

Run `tdg setup` inside an actor directory to configure the first connection and default together. After that baseline exists, add or update a connection without changing the default, or select a different default without writing credentials:

```bash
tdg setup provider openai '{"env":["OPENAI_API_KEY"]}'
tdg setup default --provider openai --model gpt-5.2
```

Known providers supply their standard endpoint and protocol. Put additional public connection fields in the same JSON object. Amazon Bedrock requires its gateway endpoint and AWS region:

```bash
tdg setup provider amazon-bedrock '{"baseUrl":"https://gateway.example.com/bedrock","region":"ap-southeast-1","env":["CLOUDFLARE_API_TOKEN"]}'
```

A custom provider declares its endpoint and protocol:

```bash
tdg setup provider private-gateway '{"baseUrl":"https://models.example.com/v1","protocol":"openai-responses","env":["PRIVATE_MODEL_KEY"]}'
```

Interactive setup stores local credentials in `.dev.vars` with mode 0600 and adds `.dev.vars*` to `.gitignore`. It never prints a stored credential. Project configuration stays in `wrangler.jsonc` and `celld.jsonc`. Setup writes connections and model definitions to `models.lock.json`. It preserves existing definitions and imports missing ones. Use `tdg models lock` to refresh definitions that have a registry source.

Setup preserves unrelated platform settings, JSONC comments, local secret entries, and other provider connections. The model services select the provider implementation from the configured protocol. Configuration rejects unsupported protocols.

## Configuration precedence

A command flag takes precedence over an environment variable. An environment variable takes precedence over `~/.tardigrade/config.json`. The configuration file takes precedence over the default. This order applies to remote URL and token settings.

| Setting | Flag | Environment | Default |
| --- | --- | --- | --- |
| Server to call | `--url` | | `http://localhost:4242` |
| Bearer token | `--token` | `TARDIGRADE_TOKEN` | none |
| Actor instance | `--actor` | | `main` |
| Project configuration | | `TARDIGRADE_CONFIG_PATH` | `wrangler.jsonc` |
| Model catalog cache | | `TARDIGRADE_MODEL_CATALOG_CACHE` | `.tardigrade/models.json` |
| Provider credentials | | Variables named by each provider's `env` list | Values saved by interactive setup in `.dev.vars` |

The generated `bun run dev` script loads `.dev.vars` and starts `server.ts`. It stores instance databases in `.tardigrade/data/`, with each instance's thread databases in a sibling `.sqlite.threads/` directory. Keep these directories present until the server stops. A deployment reads credentials from its platform secret store. Edit `server.ts` to supply application Effect services or change the server composition.

## Validate and run locally

Validate the actor's component and method seams before building or deploying:

```bash
tdg lint actor.ts
tdg build actor.ts
bun run dev
```

`tdg lint` fails when a declared method has no handler, a component handles an absent method, several components handle the same method, or a fixed actor reference calls an undeclared method. Pass `--json` to inspect each method and outgoing call seam.

## Discover providers and models

Use `--model-registry URL` with `tdg init`, `tdg setup`, or `tdg models lock` to select a models.dev-compatible JSON registry. The flag also works with `tdg setup provider` and `tdg setup default`.

```sh
tdg init my-agent --model-registry https://models.example.com/api.json
tdg models lock --model-registry https://models.example.com/api.json
```

For imports, the source order is the flag, `TARDIGRADE_MODEL_CATALOG_URL`, `vars.TARDIGRADE_CONFIG.modelRegistry`, then the default registry. Successful commands save an explicit flag or environment source in project configuration. Each imported model records its source URL in the lock. Refresh uses those per-model URLs. An explicit flag or environment source overrides them.

The model registry supplies definitions during setup and explicit lock updates. Its local cache is `.tardigrade/models.json`. Bun and Cloudflare use the lock for inference and model discovery. Neither runtime contacts the registry. The runtime rejects invalid definitions and policy references to absent models.

Inspect provider requirements and search models through a running server:

```bash
tdg providers --search gateway --limit 20 --json
tdg models --provider openrouter --search claude --limit 20 --json
```

Each response includes `revision`, `status`, `refreshed_at`, `total`, `limit`, `items`, and an optional `next_cursor`. Pass that cursor with the same filters to read the next page. Restart at the first page when the catalog revision or query changes.

## Runtime model lock

`models.lock.json` contains provider connections and complete model definitions. Models refer to providers by ID. Each `(provider, model_id)` pair must be unique. Provider credentials stay in environment variables.

```json
{
  "schema": 2,
  "providers": {
    "openrouter": {
      "protocol": "openai-chat-completions",
      "baseUrl": "https://openrouter.ai/api/v1",
      "env": ["OPENROUTER_API_KEY"]
    },
    "localhost": {
      "protocol": "openai-chat-completions",
      "baseUrl": "http://localhost:8080/v1",
      "env": ["API_KEY"]
    }
  },
  "models": [
    {
      "provider": "openrouter",
      "model_id": "vendor/model-a",
      "contextWindowTokens": 128000,
      "maxOutputTokens": 8192,
      "toolCall": true,
      "source": "https://models.dev/api.json"
    },
    {
      "provider": "localhost",
      "model_id": "qwen-local",
      "contextWindowTokens": 32768,
      "toolCall": true
    }
  ]
}
```

Each model requires a positive integer `contextWindowTokens`. Optional fields include `maxOutputTokens`, `toolCall`, `structuredOutput`, input and output modalities, pricing, and protocol-specific `options`. The optional `source` is a registry URL. Refresh looks up the same provider and model ID at that URL. Entries without `source` are manual definitions.

Project manifests contain selection policy:

```json
{
  "vars": {
    "TARDIGRADE_CONFIG": {
      "models": {
        "default": { "provider": "localhost", "model_id": "qwen-local" },
        "allow": "*"
      }
    }
  }
}
```

`allow: "*"` exposes all locked models. Explicit selectors narrow that set. Changes to policy do not require lock regeneration.

## In-memory model locks

`ModelLock` is an Effect service. Applications can supply an object directly, without a file or registry loader:

```ts
import { Effect } from "effect"
import { layerModelLock, ModelLock } from "tardie/model/lock"

const lock = layerModelLock({
  schema: 2,
  providers: {
    localhost: {
      protocol: "openai-chat-completions",
      baseUrl: "http://localhost:8080/v1",
      env: ["API_KEY"]
    }
  },
  models: [{ provider: "localhost", model_id: "qwen-local", contextWindowTokens: 32768 }]
})

const definitions = await Effect.runPromise(ModelLock.pipe(Effect.provide(lock)))
```

`layerFileModelLock(path)` supplies the same service from an injected Effect `FileSystem`. Both layers validate the same schema. `modelLayerFromLock(policy, credentials)` consumes this service for inference. `bunModelServices({ env, lock })` accepts the layer directly. Worker applications pass the lock value as `workerModelServices({ scope: definitions })`.

## Programmatic registry

`ModelRegistry` supplies definitions for imports and updates. Its `load` method receives a cache policy, an optional provider scope, and an optional source URL. A service can declare its default `source` URL for imported entries.

```ts
import { Effect, Layer } from "effect"
import { ModelRegistry } from "tardie/model/registry"
import { resolveModelLock } from "tardie/model/resolution"

const registry = Layer.succeed(ModelRegistry)({
  source: "https://models.example.com/api.json",
  load: () => Effect.succeed(snapshot)
})

const lock = await Effect.runPromise(
  resolveModelLock(config, { previous }).pipe(Effect.provide(registry))
)
```

Here, `snapshot` is a validated catalog, `config` supplies import connections and policy, and `previous` is an optional existing lock. Resolution preserves existing definitions and imports missing ones. Pass `refresh: true` to refresh sourced metadata. Complete custom definitions require no registry service. Missing definitions without a registry produce `ModelRegistryError`. Invalid definitions produce `ModelLockResolutionError`.

`layerHttpModelRegistry` implements HTTP access with an explicit source URL, timeout, and cache repository. The CLI uses this layer by default. Embedded commands and setup prompts preserve an injected `ModelRegistry` service.

## Custom models and updates

Add custom providers and models directly to the lock, or supply a definition during initialization:

```bash
tdg init local-agent --provider localhost --provider-config '{"protocol":"openai-chat-completions","baseUrl":"http://localhost:8080/v1","env":["API_KEY"],"models":{"qwen-local":{"metadata":{"contextWindowTokens":32768,"maxOutputTokens":4096,"toolCall":true}}}}' --default-model qwen-local
```

The CLI writes these definitions to the lock. Interactive setup asks for context size, an optional output limit, and tool support for an unlisted model.

```bash
tdg models lock
```

This command refreshes metadata and pricing for entries with `source`. It preserves manual definitions, provider connections, and request options. To keep an edited definition independent of future refreshes, remove its `source`. If any source lacks a complete definition, the command fails and preserves the saved lock. Successful writes replace the lock atomically.

For a schema-1 project, setup commands migrate saved metadata and manifest connections into schema 2. `tdg models lock` also migrates the project, then refreshes sourced definitions. Migration writes the lock before removing provider definitions from platform manifests. Runtime hosts require schema 2.

Restart the Bun server or redeploy the Worker to load lock edits.

## Call and control methods

Use `tdg thread create --name root` to allocate a named root before invoking it. Omit `--name` for a host-generated friendly name. The command prints the assigned thread ID; `--json` prints its actor, instance, and thread coordinates. Pass the assigned ID to `--thread` when calling a method.

`tdg call` creates a thread unless `--thread` names an existing thread. It waits for completion by default. Use `--no-wait` to print the durable handle immediately. Use the returned thread and invocation ID to read state or request cancellation:

```bash
tdg methods --json
tdg thread create --name root
tdg call message '{"text":"What is the weather in Singapore?"}' --no-wait --thread root --id m1
tdg call state message m1 --thread root
tdg call cancel message m1 --thread root --reason "operator stopped it"
```

Reuse `--id` for an idempotent retry. `tdg call state` and `tdg call cancel` require the same actor instance, thread, method, and invocation ID as the original call. The server resolves the active execution epoch.

Use `tdg ls` to list threads and `tdg events <thread>` to inspect a thread's event log. Remote calls add the server connection and actor instance:

```bash
tdg ls --url https://tardigrade.example.com --token "$TOKEN" --actor researcher
tdg events root --types TurnFailed --actor researcher
```

## Deploy

Deploy the generated Worker through either supported platform CLI:

```bash
bunx wrangler deploy
celld deploy --config celld.jsonc --dry-run
celld deploy --config celld.jsonc
```

Set the provider variables named by each connection in the platform secret store before the actor handles model calls. See the [Cloudflare guide](../platforms/cloudflare.mdx) for Worker configuration and the [Celld guide](../platforms/celld.mdx) for fleet storage, variables, and rollout behavior.
