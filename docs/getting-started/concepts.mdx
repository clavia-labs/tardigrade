Tardigrade builds an agent harness from a small set of primitives. Events record what happened. Projections turn those events into state. Components compose projections into views and enabled work. The runtime executes that work and records its outcome as more events.

<PrimitiveDiagram />

<ConceptSection kind="events">
  <div className="concept-copy">
    <h2>Events</h2>
    <p>An event is an immutable fact. Every input, decision, and durable outcome is appended to a thread's event log. Existing events never change.</p>
    <p>The event log is the source of truth. A process can stop, move to another host, or start again and recover the same behavior from the stored events.</p>
  </div>

  <ConceptInterface>
    ```ts
    interface Event {
      type: string
      [field: string]: unknown
    }
    ```
  </ConceptInterface>
</ConceptSection>

<ConceptSection kind="projections">
  <div className="concept-copy">
    <h2>Projections</h2>
    <p>A projection is a Moore-style machine whose inputs are events. It creates an initial state, steps that state forward for each event, and reads a value from the current state.</p>
    <p>The state is a compact summary of the history that can still affect the projection's output. During replay, Tardigrade folds the complete log through the machine. During live execution, it retains the state and steps only the new event tail.</p>
  </div>

  <ConceptInterface>
    ```ts
    interface Machine<Input, State, Output> {
      initial(): State
      step(state: State, input: Input): State
      output(state: State): Output
    }

    type Projection<State, Value> =
      Machine<Event, State, Value>
    ```
  </ConceptInterface>
</ConceptSection>

<ConceptSection kind="components">
  <div className="concept-copy">
    <h2>Components</h2>
    <p>A component is a named projection. Its output contains a view for its parent and the transitions that are enabled in the current state.</p>
    <p>Components are pure. Given the same state, they produce the same output without performing external work. Components can contain other components, which lets an actor combine inference, tools, budgets, compaction, permissions, and output policies.</p>
    <p>Effects that call an LLM receive Effect’s <code>LanguageModel</code> service from the host. Shared model utilities collect streams, enforce supplied request timeouts, and encode provider errors. Each component owns its prompts and interpretation: inference derives tool requests and turn outcomes, while compaction accepts a summary and records its checkpoint. The model package has no dependency on the agent package.</p>
  </div>

  <ConceptInterface>
    ```ts
    interface ComponentOutput<View, Requirements> {
      view: View
      transitions: ReadonlyArray<Transition<never, Requirements>>
    }

    interface Component<View, Requirements> {
      name: string
      machine: Projection<unknown,
        ComponentOutput<View, Requirements>>
    }
    ```
  </ConceptInterface>

  <p className="concept-bridge-copy">Component authors keep their state type through `component`. Tardigrade erases that private type only when it composes different component machines.</p>

  <ConceptInterface>
    ```ts
    import { component } from "tardie/core"

    const counter = component({
      name: "counter",
      initial: () => 0,
      step: (count, event) =>
        event.type === "Counted" ? count + 1 : count,
      output: (count) => ({
        view: count,
        transitions: []
      })
    })
    ```
  </ConceptInterface>

  <div className="compaction-example-copy">
    <h3>Example: compaction</h3>
    <p>Before an inference request, compaction checks the active model's context window from model metadata. With a 128k window and the default `triggerRatio: 0.8`, 104k tokens crosses the threshold and triggers a summary of the older span. The effect appends `CompactionCompleted`. Later model requests use its summary with a 64k-token tail, while the full event log remains available. Set `triggerRatio` and `retainRatio` on `compaction()` to change these thresholds.</p>
  </div>

<ConceptSection kind="views">
  <div className="concept-copy">
    <h2>Views</h2>
    <p>A view is the value a component exposes to its parent. A system component contributes instructions. A tool component contributes tool definitions. A transcript projection contributes model messages.</p>
    <p>A parent combines child views through an associative view algebra. This gives each component a small interface while the complete component tree produces the context needed by inference or another parent.</p>
  </div>

  <ConceptInterface>
    ```ts
    interface ViewAlgebra<View> {
      empty: View
      combine(left: View, right: View): View
    }
    ```
  </ConceptInterface>
</ConceptSection>

<ConceptSection kind="transitions">
  <div className="concept-copy">
    <h2>Transitions</h2>
    <p>A transition describes one unit of work enabled by projected state. An intent proposes events without contacting the outside world. An effect performs external work and returns events that record its outcome.</p>
    <p>Components declare work through the context supplied to `step(state, event, context)`. A local tag, the component name, and the owning event position identify each transition. The runtime attaches that reference to the final event in its result batch and uses recorded completions to avoid repeating finished work. The actor is settled when no transition remains enabled.</p>
  </div>

  <ConceptInterface>
    ```ts
    import { component } from "tardie/core"
    import type { TransitionContext } from "tardie/core/component"
    import type { Transition } from "tardie/core/transition"

    type Pending = {
      context: TransitionContext
      work: Transition<never>
    }

    const acknowledge = component<Pending | undefined, undefined>({
      name: "acknowledge",
      initial: () => undefined,
      step: (pending, event, context) => {
        if (event.type === "Requested") {
          return {
            context,
            work: context.intent("ack", { type: "Acknowledged" })
          }
        }
        return pending?.context.matches("ack", event) ? undefined : pending
      },
      output: (pending) => ({
        view: undefined,
        transitions: pending === undefined ? [] : [pending.work]
      })
    })
    ```
  </ConceptInterface>

  <p className="concept-bridge-copy">This component acknowledges the latest request. It retains the owning context until its completion arrives. `context.effect(tag, { input, act })` declares external work; `act(input, { signal })` returns an Effect containing the result events. Reuse a tag for retries of the same operation. A new operation needs a different tag or owning event.</p>

  <div className="transition-example-copy">
    <h3>Example: a tool-calling agent</h3>
    <p>A message enables inference. `ModelReturned` records the response and its usage; each requested tool also gets a `ToolCalled` event linked by `responseId`. A model tool call enables service work. Its result enables inference again. A final response completes the method call.</p>
  </div>

<ConceptSection kind="actors">
  <div className="concept-copy">
    <h2>Actors</h2>
    <p>An actor gives the composed machines an identity and a callable interface. Each actor instance can own many threads, and each thread has its own event log and projected state.</p>
    <p>Methods accept work from callers. Components define how the actor responds. The runtime keeps executing enabled transitions until the thread settles.</p>
  </div>

  <ConceptInterface>
    ```ts
    import { actor } from "tardie/core"
    import { agentMessageMethod, infer, outputValidateOnce } from "tardie/agent"

    const assistant = actor({
      name: "assistant",
      methods: { message: agentMessageMethod },
      components: [infer([outputValidateOnce])]
    })
    ```
  </ConceptInterface>

  <ActorDiagram />
</ConceptSection>

<ConceptSection kind="methods">
  <div className="concept-copy">
    <h2>Methods</h2>
    <p>Methods define the actor's typed callable surface. Each method validates its input, turns a valid call into an event, and projects the call's pending, completed, failed, or cancelled state.</p>
    <p>A caller supplies a call identifier. Repeating that call is absorbed by the log, and the caller can read the same durable result after a retry or process restart. The method projection tracks history and exposes `currentEpoch(id)` and `invocationState(invocation)` queries.</p>
  </div>

  <ConceptInterface>
    ```ts
    import { actorMethod } from "tardie/core"
    import { input, output, event, projection } from "./message-contract"

    const message = actorMethod({
      input,
      output,
      event,
      projection
    })
    ```
  </ConceptInterface>

  <p className="concept-bridge-copy">The application supplies the input and output schemas, event builder, and projection. The projection has `initial`, `step`, and `output`; its output exposes the lifecycle queries. An optional `cancellation` declaration provides the cancellation event builder.</p>

  </div>
</ConceptSection>
