## Declare a library

```ts
import { Schema } from "effect"
import { Rpc } from "effect/rpc"
import { defineLibrary, MethodDescription } from "tardie/libraries"

export const calculator = defineLibrary({
  name: "calculator",
  description: "Arithmetic tools",
  toolNames: { multiply: "multiply" },
  methods: [Rpc.make("multiply", {
    payload: Schema.Struct({ left: Schema.Finite, right: Schema.Finite }),
    success: Schema.Finite,
  }).annotate(MethodDescription, "Multiply two numbers")],
})
```

## Implement the methods

```ts
import { Effect } from "effect"
import { toolActs } from "tardie/agent/services"
import { calculator } from "./calculator"

const calculatorLive = calculator.implement({
  multiply: ({ left, right }) => Effect.succeed(left * right),
})

export const calculatorActs = toolActs([calculatorLive])
```

## Use a library in an actor

```ts
import { Effect } from "effect"
import { atom, defineActor } from "tardie/core"
import { agentMethods, compact, infer, messages, tools } from "tardie/agent"
import { calculator } from "./calculator"

export const meeseeks = defineActor("meeseeks", Effect.gen(function* () {
  const system = atom("Use the calculator for arithmetic.")
  const arithmetic = yield* tools([calculator])
  const context = yield* compact(messages)
  const agent = yield* infer(get => ({
    system: get(system),
    tools: get(arithmetic),
    context: get(context),
  }))

  return { atom: agent, methods: agentMethods }
}))
```

## Recall event history

The `log` library exposes schema discovery and read-only SQL queries for the calling thread's history, independently of its compacted conversation context.

```ts
import { agent } from "tardie/agent"
import { log as recall } from "tardie/libraries"

export default agent({
  name: "researcher",
  system: "You are a helpful assistant.",
  tools: [recall],
})
```

Include `logTools()` in the host's `toolActs` implementations. The runtime provides the thread-scoped `EventLog` service and current actor schemas on Bun and Cloudflare. The service executes read-only SQL on the existing thread database on both platforms.

```ts
import { toolActs } from "tardie/agent/services"
import { DEFAULT_LOG_POLICY, logTools } from "tardie/libraries"

export const recallActs = toolActs([logTools({
  ...DEFAULT_LOG_POLICY,
  maxResults: 10,
})])
```

### Discover schemas

`log.describe({ type?, cursor?, limit? })` is exposed to the model as `recall_describe`. Omit `type` or supply an empty string to list event types and SQL table columns. Supply an event type to retrieve its current declared JSON Schemas, observed field kinds, and samples with journal positions. `nextCursor` continues the event type inventory.

Current declarations and observed shapes are reported separately. Older records can have fields absent from the current schema, and observed event types can lack a current declaration. `observedThrough` is the exclusive boundary of inspected history; `observedComplete` reports whether that inspection covered the snapshot. Samples and schema text carry individual `truncated` flags. Field descriptions in the actor's schemas explain domain meaning without embedding event names or field names in the agent's system prompt.

### Query history

`log.query({ sql, from?, through? })` is exposed to the model as `recall_sql`. It accepts one read-only SQLite SELECT over `events(position, recorded_at, type, event, record)`. `type` and JSON `event` expose domain events inside inbound message envelopes; JSON `record` retains the observed envelope and metadata. Use discovery to inspect event fields before constructing JSON predicates.

The input window contains at most `maxScanEvents` records starting at `from`. Results report `scannedThrough`, `next`, and the exclusive `through` boundary. Continue with `from: next` and the same `through` to retain the history prefix. Aggregations cover only the reported window. Results return JSON `text` containing columns and rows, a `moreRows` flag for the result count bound, and a `truncated` flag for the text bound.

### Configure limits

`DEFAULT_LOG_POLICY` exports defaults of 20 results per page or SQL query, 500 inspected events, 4,096 characters per schema, sample, or SQL result, two samples per event type, and 8,192 characters per SQL query. `logTools` accepts overrides for `maxResults`, `maxScanEvents`, `maxRecordChars`, `maxSamples`, and `maxQueryChars`. Each response includes the applied policy and pagination or truncation metadata.

`EventLog.query` uses the thread's existing SQLite connection. The journal decodes the bounded history window, including chunked records, into the public `events` surface using SQLite's `json_each`. Writes, administration statements, multiple statements, and references to private database names are rejected. Native queries run synchronously under the host platform's execution limits.
