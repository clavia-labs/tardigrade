### Prerequisites

1. The latest [Tardie CLI](/docs/cli)
2. An LLM API key from a provider of your choice

For deployment, install either the [Wrangler CLI](https://developers.cloudflare.com/workers/wrangler/install-and-update/) for Cloudflare or the [Celld CLI](https://celld.dev/docs/) for your own cloud.

### Initialize your project

First, install the [Tardie CLI](/docs/cli).

<InstallCommand packageName="tardie@latest" global />

Now, use the [Tardie CLI](/docs/cli) to create a new `meeseeks` directory and configure a language model provider.

```bash variant="single"
tdg init meeseeks --template agent
```

Initialization locks the selected model. Run `tdg models lock` to include additional configured models with complete context metadata.

After the setup, you should see the following files:

<Filesystem root="meeseeks/">
  - `actor.ts` Actor and atoms
  - `services.ts` Model and library implementations
  - `generated/providers.ts` Configured model implementations
  - `server.ts` Bun server entry
  - `worker.ts` Cloudflare and Celld Worker entry
  - `wrangler.jsonc` Cloudflare Worker configuration
  - `celld.jsonc` Self-hosted Celld configuration
  - `models.lock.json` Resolved model metadata
  - `package.json` Dependencies and module metadata
</Filesystem>

Move into the new project directory:

```bash variant="single"
cd meeseeks
```

### Define your first actor

#### Hello world!

In this guide, we'll implement a simple agent with a tool that returns dummy weather data for a given city. In another guide, we'll explore a more advanced setup by building an agent that can execute JavaScript code, call MCP servers, and run subagents within a sandbox.

As you follow along, you will see tip boxes that you can expand to learn what happens behind the scenes.

<Tip title="About these tips">
These notes explain what Tardigrade is doing behind the scenes. You can skip them and still complete the guide.
</Tip>

Within `actor.ts`, you will see the following code:

```ts expanded
import { Effect, Schema } from "effect"
import { Rpc } from "effect/unstable/rpc"
import { atom, defineActor } from "tardie/core"
import { agentMethods, compact, infer, messages, tools as libraryTools } from "tardie/agent"
import { defineLibrary, MethodDescription, MethodHints } from "tardie/libraries"

const actorName = "meeseeks"

const actorInstructions = `
Answer questions about the weather.
Use the weather tool for current conditions.
`.trim()

export const weather = defineLibrary({
  name: "weather",
  description: "Weather information",
  toolNames: { current: "get_weather" },
  methods: [Rpc.make("current", {
    payload: Schema.Struct({ city: Schema.String }),
    success: Schema.Struct({ city: Schema.String, temperature: Schema.Finite }),
  })
    .annotate(MethodDescription, "Get example weather data for a city")
    .annotate(MethodHints, { readOnlyHint: true, openWorldHint: false })],
})

export default defineActor(actorName, Effect.gen(function* () {
  const system = atom(actorInstructions)
  const tools = yield* libraryTools([weather])
  const context = yield* compact(messages)
  const agent = yield* infer(get => ({
    system: get(system),
    tools: get(tools),
    context: get(context),
  }))
  return { atom: agent, methods: agentMethods }
}))
```

`messages` derives message history from the event log. `compact` prepares model context, and `infer` proposes model calls. The actor composes these atoms and exposes `agentMethods`.

The weather library declares a typed method with Effect RPC. Its implementation belongs in `services.ts`:

```ts
const tools = weather.implement({
  current: ({ city }) => Effect.succeed({ city, temperature: 21 }),
})
```

The example returns dummy weather data. Replace the handler with your weather service. `toolActs([tools])` supplies the handler to the runtime; the actor sees its method schema and annotations.

### Running it locally

Run the generated Bun API server directly:

```bash variant="single"
bun run dev
```

The server runs on `localhost:4242` by default. Set `PORT` to change it. Check `curl localhost:4242/healthz` from another shell to confirm it is ready. Edit `server.ts` to change how the actor and API are assembled.

### Send your first message

Once you have the agent running, create a root thread named `quickstart`, then send it your first message. The creation command prints the assigned thread ID.

```bash
tdg thread create --name quickstart
tdg call message '{"text":"What is the weather in Singapore?"}' --thread quickstart
```

The `message` method records a `TurnRequested` event. Model and tool results update durable atoms, and a `TurnSettled` event completes the call with `{ text: string }`. Each call has an invocation ID. To safely retry a call, supply the same `--id` and the same input.

### Inspecting the actor logs

After your call, you will see `.tardigrade/`. This directory holds one SQLite database for each actor instance. An event log is an immutable, append-only ledger of events sent to the actor and events generated by the actor.

<Filesystem root=".tardigrade/">
  - `<actor-instance>.sqlite` Registry for the `main` actor instance
  - `<actor-instance>.sqlite.threads/`
    - `<thread>.sqlite` Event log for the `quickstart` thread
</Filesystem>

A simplified view of the message includes the following events. The log also records the model requests and responses.

These events persist across runs. Each thread has a separate SQLite event database in the `.sqlite.threads/` directory beside its actor instance database. Set `TARDIGRADE_ACTOR_DATA` to change the storage directory.

You can use the following command to view the events:

```bash variant="single"
tdg events <thread>
```

If you used the command in this guide, the first message landed in a thread called `quickstart`. To view its events, run:

```bash variant="single"
tdg events quickstart
```

### Send a follow up message

To send a follow up message, simply send another message to the same thread:

```bash variant="single"
tdg call message '{"text":"How about San Francisco?"}' --thread quickstart
```

### Deploy your agent

Set your provider credential as a Worker secret before deploying. For example, with OpenRouter:

```bash variant="single"
bunx wrangler secret put OPENROUTER_API_KEY
```

The generated Worker uses an `ActorDO` binding and the same actor, service layer, and model lock as the Bun server. Deploy it:

```bash variant="single"
bun run deploy:cloudflare
```

To deploy it on your own cloud, use Celld:

```bash variant="single"
bun run deploy:celld
```

### Send a message to your cloud agent

Once your deployment is ready, create a root thread on the remote host, then invoke its message method. Set `ACTOR_URL` to your deployment URL.

```bash
tdg thread create --name quickstart --url "$ACTOR_URL"
tdg call message '{"text":"What is the weather in Singapore?"}' --thread quickstart --url "$ACTOR_URL"
```
