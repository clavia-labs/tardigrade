Building an agent is challenging. This is especially true as the horizons over which they operate is ever expanding. As tasks get harder, behaviors become harder to reason about. The harnesses we build around our agents get ever more complex. Tardigrade presents a new way of thinking about agent harnesses, and as a result, a way to simplify this complexity.

In a typical agent harness, your core model loop would be something like this:

```ts
type AgentPolicy = {
  readonly contextWindow: number
  readonly compactAt: number
  readonly maxTurns: number
}

const runAgent = async (
  messages: Message[],
  policy: AgentPolicy
): Promise<string> => {
  let turns = 0

  while (turns < policy.maxTurns) {
    if (tokenCount(messages) >= policy.contextWindow * policy.compactAt) {
      messages = await compact(messages)
    }

    const response = await model.generate({ messages, system, tools })
    messages.push(response)

    if (response.toolCalls.length === 0) return response.text

    for (const call of response.toolCalls) {
      const result = await canUseTool(call)
        ? await tools.execute(call)
        : toolDenied(call)
      messages.push(result)
    }

    turns += 1
  }

  throw new Error("Turn limit reached")
}
```

It doesn't seem like a problem initially, but as you add more stateful conditions (permissions, budgets for tool calls and tokens, subagents, sandboxed code execution), it starts to add up. It is not obvious which part of your code led to a specific agent behavior, nor how they interact with each other.

What if there was a more declarative  and composable way to author behavior, something like react? Once you frame an agent's harness as an interface for agents, it become a rendering problem and the frontend community had already solved for this! React defined the user interface as a component tree, and each component was a function of state. Similarly, Tardigrade defines an agent harness as a composition of components, and each component is a function of state, projected from an immutable event log.

### The Tardigrade pattern

If you asked me to compress Tardigrade's single most important insight, it is this:

<Math expression="\text{behavior} = f(\text{immutable event log})" />

An agent harness could be viewed as a composition of behaviors, which are defined as pure functions over an immutable log. This idea grew out of the realization that building an agent harness is not much different from building a user interface. A harness is an interface built for an agent to effectively interact with the world. Interacting with the world means making state changes given an existing state.

### Example: Compaction

For example, let's take compaction. With tardigrade, adding compaction to your agent looks like this:

```ts highlight="12"
const boundedContext = compaction({
  contextWindowTokens: 128_000,
  fireRatio: 0.8,
  keepRatio: 0.5
})

export const researcher = actor({
  name: "researcher",
  methods: agentMethods,
  components: [infer([
    system("Research the given topic and cite your sources."),
    boundedContext,
    nativeOutput
  ])]
})
```

You can simply plug this out of your agent or test various other compaction policies without affecting the other defined behaviors of the agent. This is made possible because every component is defined as a pure function of state. A component has the following interface:

```ts
interface IncrementalComponentDefinition<State, View, Requirements = never> {
  readonly name: string
  readonly initial: () => State
  readonly step: (state: State, event: Event) => State
  readonly output: (state: State) => {
    readonly view: View
    readonly transitions: ReadonlyArray<Transition<never, Requirements>>
  }
}
```

Compaction follows the same pattern. Each event updates its state. When the context grows too large, it asks the runtime to summarize older events and uses that summary in future model calls.
