Building an agent is challenging. As tasks get harder, behaviors become harder to reason about, and the harness we build around our agents get ever more complex. Tardigrade presents a way to simplify this complexity, by proposing a new way of thinking about agent harnesses.

In a typical agent harness, your core model loop would be something like this:

```ts
type AgentPolicy = {
  readonly contextWindow: number
  readonly compactAt: number
  readonly maxTurns: number
}

const runAgent = async (
  messages: Message[],
  policy: AgentPolicy
): Promise<string> => {
  let turns = 0

  while (turns < policy.maxTurns) {
    if (tokenCount(messages) >= policy.contextWindow * policy.compactAt) {
      messages = await compact(messages)
    }

    const response = await model.generate({ messages, system, tools })
    messages.push(response)

    if (response.toolCalls.length === 0) return response.text

    for (const call of response.toolCalls) {
      const result = await canUseTool(call)
        ? await tools.execute(call)
        : toolDenied(call)
      messages.push(result)
    }

    turns += 1
  }

  throw new Error("Turn limit reached")
}
```

It doesn't seem like a problem initially, but as you add more stateful conditions (permissions, budgets, subagents), it starts to add up. It is not obvious which part of your code led to a specific agent behavior, nor how they interact with each other.

What if there was a more declarative  and composable way to author behavior? Tardigrade grew out of the realization that an agent harness isn't very different from a user interface. A harness is simply an interface for an agent to effectively interact with the world and accomplish goals. Just like how traditional user interfaces help humans effectively interact with the digital world. Once you frame it this way, it become a rendering problem and the frontend community had already solved for this!&#x20;

React defined the user interface as a component tree, and each component was a function of state. Similarly, Tardigrade defines an agent harness as a composition of components, and each component is a state machine, with state as projections from an immutable event log.

### The Tardigrade pattern

If you asked me to compress Tardigrade's single most important insight, it is this:

<Math expression="\text{behavior} = f(\text{immutable event log})" />

If you can describe the behavior you want to see in simple english, you should be able to define it as a function of the event log. An agent harness could then be viewed as a composition of such behaviors.

### Example: Compaction

For example, let's take compaction. In simple english, you could describe compaction as follows:

> When the token count of the conversation sent to inference reaches a certain threshold, use a language model to summarise a certain chunk of the conversation. Once summarized, append it to the event log as
>
> `CompactionCompleted`
>
>  holding the summary. And then for every subsequent model call, attach this summary and a tail of the existing conversation.

As a state machine written over the event log, it looks like this:

Once you've defined this behavior, now you can composed it with other such behaviors defined in a similar manner.

```ts highlight="12"
const boundedContext = compaction({
  contextWindowTokens: 128_000,
  fireRatio: 0.8,
  keepRatio: 0.5
})

export const researcher = actor({
  name: "researcher",
  methods: agentMethods,
  components: [infer([
    system("Research the given topic and cite your sources."),
    boundedContext,
    nativeOutput
  ])]
})
```

You can simply plug this out of your agent or test various other compaction policies without affecting the other defined behaviors of the agent. This is made possible because every component is defined as a pure function of state. A component has the following interface:

```ts
interface IncrementalComponentDefinition<State, View, Requirements = never> {
  readonly name: string
  readonly initial: () => State
  readonly step: (state: State, event: Event) => State
  readonly output: (state: State) => {
    readonly view: View
    readonly transitions: ReadonlyArray<Transition<never, Requirements>>
  }
}
```

Compaction follows the same pattern. Each event updates its state. When the context grows too large, it asks the runtime to summarize older events and uses that summary in future model calls.

We can extend this approach to build subagents, codemode, recursive language models and so on. Your imagination is the limit here!
